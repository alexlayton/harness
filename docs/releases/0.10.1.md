# Harness 0.10.1

This is a bug fix release. It closes a set of state-handling bugs found in an
audit of the agent, sessions, providers, MCP, tools, ACP, and TUI, and it
changes how `/ask` shows its answer.

## Fixes

### Providers and authentication

- A refresh no longer reuses a stale refresh token. It now fails closed when the
  stored credential cannot be read, and it keeps the newly refreshed tokens when
  another process changed only account details such as the email or organization.
- Login credentials are written under the same lock as refreshes, so a refresh
  in progress cannot overwrite a fresh login.
- OpenAI Chat tool calls are held until the stream finishes. A stream that is cut
  off after `finish_reason` now fails as interrupted instead of running tool
  calls from an incomplete response.
- The Anthropic, OpenAI Responses, and Codex stream parsers reject duplicate or
  malformed events and treat a failure as final. Unmodeled Anthropic blocks such
  as `server_tool_use` are still accepted.
- A `[secrets].env` entry whose variable is unset is skipped instead of failing
  launch.

### Agent, sessions, and compaction

- Prewalk keeps its restore point when a model switch is rejected, and it no
  longer arms on the wrong model. It now hands off after an interrupted `edit`
  round, but not while Harness is shutting down.
- A subagent no longer runs tools on its final report turn, and its trimmed
  history stays valid.
- Recovery notes survive compaction, each kind of recovery has its own budget,
  and a model's context window learned from an overflow error is not overwritten
  by stale metadata.
- A session append in memory can no longer leave the file cursor behind, which
  could write a sequence gap that made the session fail to load.
- After an error, pending tool calls are closed when the next turn starts. Logs
  written by earlier versions still load. Compaction also works after an error
  in the middle of a tool call.
- Deferred session syncs are shared across store handles and are kept when a sync
  fails.

### Tools, MCP, and ACP

- Bash reports output that was lost, and reports a failed wait as an error
  instead of a cancellation.
- Codemode keeps the output printed before a cancel or timeout, and nested tool
  calls are only accepted while a workflow is running.
- File locks use a stable key for files that do not exist yet.
- MCP tracks the state of each server, and calls to a dead server fail at once.
  The close path always cleans up, and I/O errors are no longer reported as
  oversized frames.
- ACP refuses to load a session while it is being deleted, reports an agent
  failure instead of a clean cancel, and drops tool calls left open when a turn
  ends. A reasoning delta no longer clears a pending error, which matches
  `harness prompt` and the SDK.
- `harness prompt` and the SDK share one rule for the final answer. A Ctrl-C that
  arrives after the answer is complete no longer turns it into exit code 130.

### TUI

- A failed `/sessions` or model list request no longer prints an unrequested
  list or blocks completion. Tab retries a failed request, and typing does not.
- Edits to a recalled history entry are kept, and accepting a completion
  cancels its path scan.
- A late event no longer restarts the spinner after a turn ends, and an operation
  finishing no longer clears a turn in progress.

## Changes

- `/ask` now shows its answer inline at full height. The pager and its
  `PgUp`/`PgDn` keys are gone, and Esc still closes the answer. An answer taller
  than the terminal is printed into the terminal's scrollback.

## Installation and upgrade

Run `harness update` after 0.10.1 is published. The supported CLI builds are:

- macOS on Apple silicon (`aarch64-apple-darwin`).
- macOS on Intel (`x86_64-apple-darwin`).
- Linux x86-64 with glibc 2.35 or newer (`x86_64-unknown-linux-gnu`).
- Linux arm64 with glibc 2.35 or newer (`aarch64-unknown-linux-gnu`).

Each archive includes the binary, README, header image, and MIT license. Use the
attached `SHA256SUMS` file to verify a downloaded archive, and
`gh attestation verify` to check its build provenance.

To install this version with the installer:

```sh
curl -fsSL https://raw.githubusercontent.com/alexlayton/harness/main/install.sh \
  | bash -s -- --version v0.10.1
```

The Python API is still a source-installed MVP. This release does not publish a
PyPI package or prebuilt wheels:

```text
harness-agent @ git+https://github.com/alexlayton/harness.git@v0.10.1
```

Harness still runs tools without confirmation. Bash and MCP tools have the
access of the operating-system user. Use these features only in environments
where you accept that behavior.
