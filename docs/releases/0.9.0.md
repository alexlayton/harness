# Harness 0.9.0

This release adds opt-in MCP servers that connect only for the sessions that
request them, a Linux arm64 build, and a closer Herdr integration.

## Opt-in MCP servers

A server with `enabled = false` in `[[mcp.servers]]` is configured but not
connected by default. A launch connects it only when it names the server with
`--mcp`. Repeat the flag for several servers. Use this for sensitive servers,
such as email, that you want in one session and not in all of them.

```toml
[[mcp.servers]]
name = "email"
transport = "http"
url = "https://example.com/mail-mcp"
enabled = false
```

```text
harness --mcp email
harness --mcp email --mcp calendar prompt "Summarize today's mail"
```

- `harness mcp add --disabled` adds an opt-in server.
- `harness mcp enable <name>` and `harness mcp disable <name>` toggle the
  setting.
- `harness mcp list` marks opt-in servers with `(opt-in)`.
- Selection runs before `${ENV_VAR}` expansion, so an opt-in server's
  credentials are required only in launches that request it.
- An unknown `--mcp` name is an error.
- Servers connect once per process, so `/new` and `/resume` keep the launch's
  selection.

Harness does not write `enabled` to disk when it is `true`, so existing
configs do not change. See
[Per-session servers](https://github.com/alexlayton/harness/blob/v0.9.0/docs/configuration.md#per-session-servers).

## Linux arm64

Releases now include a Linux arm64 archive
(`aarch64-unknown-linux-gnu`). It is built on a native Ubuntu 22.04 arm64
runner, so it has the same glibc 2.35 baseline as the x86-64 build. The
installer and `harness update` select the new archive on arm64 Linux.

## Herdr

The Herdr integration now follows Herdr's agent-support guide:

- When several state changes queue while a Herdr call runs, Harness sends only
  the newest state.
- For `harness worktree BRANCH` launches, the resume command enters the same
  worktree again, so a restored pane finds its workspace-scoped session.
- Harness reports the session title as display-only pane metadata and clears
  it on exit.
- The resume command repeats any `--mcp` flags from the launch.

## Installation and upgrade

From 0.8.0, run `harness update` after 0.9.0 is published. The supported CLI
builds are:

- macOS on Apple silicon (`aarch64-apple-darwin`).
- macOS on Intel (`x86_64-apple-darwin`).
- Linux x86-64 with glibc 2.35 or newer (`x86_64-unknown-linux-gnu`).
- Linux arm64 with glibc 2.35 or newer (`aarch64-unknown-linux-gnu`). New in
  this release.

Each archive includes the binary, README, header image, and MIT license. Use the
attached `SHA256SUMS` file to verify a downloaded archive, and
`gh attestation verify` to check its build provenance.

To install this version with the installer:

```sh
curl -fsSL https://raw.githubusercontent.com/alexlayton/harness/main/install.sh \
  | bash -s -- --version v0.9.0
```

The Python API is still a source-installed MVP. This release does not publish a
PyPI package or prebuilt wheels:

```text
harness-agent @ git+https://github.com/alexlayton/harness.git@v0.9.0
```

Harness still runs tools without confirmation. Bash and MCP tools have the
access of the operating-system user. Use these features only in environments
where you accept that behavior.
