# Harness 0.11.0

This release changes how the TUI renders replies. Markdown now goes through a
new in-workspace renderer, `tui-md`, which replaces ratatui. It also adds
click-to-move in the prompt and a `/copy` command, and fixes several subagent
and repaint problems.

## Changes

- Markdown replies are rendered by the new `tui-md` crate, which builds on
  crossterm. It handles wrapping, lists, quotes, alerts, tables, and
  syntax-highlighted code blocks, which use a new green TextMate theme. The TUI
  no longer depends on ratatui or tui-markdown.
- Clicking in the prompt moves the cursor there. This uses OSC 133 click
  events, so the terminal has to support them.
- New `/copy [code]` command. It copies the last reply as plain text, or with
  `code`, only its last code block. The copy is sent through OSC 52.
- Long reasoning streams as it arrives instead of appearing all at once.
- Subagent tool results are truncated only when the child's history exceeds
  its context budget. Before, every result was cut to 8 KB. The oldest results
  are now cut first, and each cut is marked.

## Fixes

- Full repaints are more reliable. A reply that is split into chunks keeps a
  single marker.
- Clicks on a row that holds only the cursor are hit-tested correctly. `/copy`
  joins chunked replies back together when notices appear between them.
- On a terminal too narrow for the wordmark, the welcome screen leaves out the
  title instead of showing a plain, misaligned "Harness" line.
- Running `/model` or updating the masker repeatedly no longer stacks provider
  decorators. The masking layer is replaced instead.
- Subagents persist the empty-reply nudge to the child session, label retries
  with the task description, and keep partial output when a stream is
  interrupted.
- Markdown rendering: empty highlighted fences keep one row, empty list items
  have no trailing gap, inline HTML stays on one row, non-breaking spaces are
  not used as break points, ANSI output emits every style attribute, and
  blocks with unresolved references are not committed early.

## Installation and upgrade

Run `harness update` after 0.11.0 is published. The supported CLI builds are:

- macOS on Apple silicon (`aarch64-apple-darwin`).
- macOS on Intel (`x86_64-apple-darwin`).
- Linux x86-64 with glibc 2.35 or newer (`x86_64-unknown-linux-gnu`).
- Linux arm64 with glibc 2.35 or newer (`aarch64-unknown-linux-gnu`).

Each archive includes the binary, README, header image, and MIT license. Use the
attached `SHA256SUMS` file to verify a downloaded archive, and
`gh attestation verify` to check its build provenance.

To install this version with the installer:

```sh
curl -fsSL https://raw.githubusercontent.com/alexlayton/harness/main/install.sh \
  | bash -s -- --version v0.11.0
```

The Python API is still a source-installed MVP. This release does not publish a
PyPI package or prebuilt wheels:

```text
harness-agent @ git+https://github.com/alexlayton/harness.git@v0.11.0
```

Harness still runs tools without confirmation. Bash and MCP tools have the
access of the operating-system user. Use these features only in environments
where you accept that behavior.
