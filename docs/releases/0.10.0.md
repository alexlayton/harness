# Harness 0.10.0

This release adds program status reports with OSC 7501 and fixes several tool
and TUI problems.

## Program status (OSC 7501)

Harness now reports what it is doing with the
[Program Status Protocol](https://www.superlogical.com/rex/docs/build/program-status)
(`OSC 7501`). Terminals and multiplexers that support it, such as the Herdr
app, can show whether Harness is working, finished, or failed. Terminals that
do not know the sequence ignore it.

| Event | State |
| --- | --- |
| A turn or command starts, or output streams | `working` |
| A turn finishes | `done` |
| A turn fails | `error`, with a short `msg` |
| The user cancels with Esc | `idle` |
| The TUI exits | `clear` |

- Reports are on by default. To turn them off, set `program_status = false`
  in the config.
- In the TUI, Harness writes a report at the start of a frame, so a report
  cannot split the frame's escape sequences.
- In `harness prompt`, reports go to stderr only when stderr is a terminal, so
  stdout stays the answer only. A headless run leaves a `done` or `error`
  record on exit.
- Inside a Herdr TUI pane, Harness sends only the Herdr TUI reports.

The Herdr integration is now named the Herdr TUI integration, because the
Herdr desktop app uses OSC 7501. The `HERDR_*` environment variables do not
change. See
[Program status](https://github.com/alexlayton/harness/blob/v0.10.0/docs/configuration.md#program-status-osc-7501).

## Fixes

- `grep` and `multigrep` accept a file as `path`. Before, a file path failed
  with "not a directory". `find` still accepts directories only.
- When a codemode snippet fails, it now returns the output of the nested calls
  that completed, so the model does not run them again.
- An unknown `tools[...]` name in codemode gives a hint instead of a bare
  `KeyError`. The hint covers the provider `_` prefix and tools that codemode
  does not expose.
- A skill turn keeps its `done` or `error` status when its operation ends.

## Installation and upgrade

From 0.9.0, run `harness update` after 0.10.0 is published. The supported CLI
builds are:

- macOS on Apple silicon (`aarch64-apple-darwin`).
- macOS on Intel (`x86_64-apple-darwin`).
- Linux x86-64 with glibc 2.35 or newer (`x86_64-unknown-linux-gnu`).
- Linux arm64 with glibc 2.35 or newer (`aarch64-unknown-linux-gnu`).

Each archive includes the binary, README, header image, and MIT license. Use the
attached `SHA256SUMS` file to verify a downloaded archive, and
`gh attestation verify` to check its build provenance.

To install this version with the installer:

```sh
curl -fsSL https://raw.githubusercontent.com/alexlayton/harness/main/install.sh \
  | bash -s -- --version v0.10.0
```

The Python API is still a source-installed MVP. This release does not publish a
PyPI package or prebuilt wheels:

```text
harness-agent @ git+https://github.com/alexlayton/harness.git@v0.10.0
```

Harness still runs tools without confirmation. Bash and MCP tools have the
access of the operating-system user. Use these features only in environments
where you accept that behavior.
