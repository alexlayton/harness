# Harness 0.7.0

This release adds isolated questions in the terminal UI, opt-in code mode, and
an initial native Python API. It also corrects stream recovery for frontends
that return only the final answer.

## Isolated questions with `/ask`

Use `/ask <question>` in the terminal UI to ask a separate one-shot question.
It uses the current provider, model, and reasoning setting, but has no
conversation history or tools. The question and answer are not added to the
conversation or session log. Press Esc to cancel the question without
cancelling the main conversation.

## Opt-in code mode

Code mode lets the model call selected built-in and MCP tools from one Python
program through `run_code`. It can use loops and conditions, filter intermediate
results, and return only the useful output. MCP structured results are available
as Python values.

Enable it in `config.toml`:

```toml
[code_mode]
enabled = true
```

Code mode is off by default. Tool calls are sequential, and each program starts
with fresh state. Execution and output have fixed limits. Nested calls have
separate session audit records. Code mode replaces the standalone `python`
tool; `bash` and `subagent` remain separate tools.

**Earlier tool changes are not rolled back after a failure or cancellation.**
Check partial results before you repeat a program. Code mode is not a sandbox.
See [Code mode](https://github.com/alexlayton/harness/blob/v0.7.0/docs/configuration.md#code-mode)
for tool selection, limits, and safety details.

## Native Python API: source-installed MVP

Run the agent inside your Python process and get the final answer as text:

```sh
CARGO_BUILD_JOBS=1 uv pip install \
  "harness-agent @ git+https://github.com/alexlayton/harness.git@v0.7.0"
```

```python
import harness

answer = harness.run(prompt="Summarize this workspace.")
print(answer)
```

The distribution name is `harness-agent`; the import name is `harness`. Install
from the repository root, with no Git subdirectory fragment. The API uses the
normal Harness configuration and credentials. Per-call options can select a
workspace, provider, model, or session, and replace or disable MCP servers and
skill directories. Ctrl-C requests cancellation and waits for native cleanup.

This is a **synchronous, text-only MVP for Python 3.10+ on macOS and Linux**.
Source installation requires a current stable Rust toolchain and native build
tools. It does not need a separate Harness executable to run. It has no async or
streaming API, timeout option, Python tool callbacks, or programmatic
cancellation. Subinterpreters and fork-after-runtime-start are not supported.

**This release does not publish a PyPI package or prebuilt Python wheels.**
The GitHub release archives contain the CLI only. Python installation is
separate from CLI installation. See the
[Python guide](https://github.com/alexlayton/harness/blob/v0.7.0/python/README.md)
for options, authentication, and lifecycle limits.

## Stream recovery

After a recoverable stream failure, headless and Python calls now request a
complete replacement answer. This prevents a missing answer prefix when the
frontend discards text from a failed response. The terminal UI and ACP retain
continuation recovery because they already show the streamed text.

## Installation and upgrade

From 0.6.1, run `harness update` after 0.7.0 is published. The supported CLI
builds are unchanged:

- macOS on Apple silicon (`aarch64-apple-darwin`).
- macOS on Intel (`x86_64-apple-darwin`).
- Linux x86-64 with glibc 2.35 or newer (`x86_64-unknown-linux-gnu`).

Each archive includes the binary, README, header image, and MIT license. Use the
attached `SHA256SUMS` file to verify a downloaded archive.

**The 0.6.0 binary cannot update itself.** If you used the Harness installer,
run it again:

```sh
curl -fsSL https://raw.githubusercontent.com/alexlayton/harness/main/install.sh \
  | bash -s -- --version v0.7.0
```

For other installation methods, replace the binary with the matching archive
or use that package manager's upgrade command.

Harness still runs tools without confirmation. Bash and MCP tools have the
access of the operating-system user. The native Python API shares process
failure risk with its host script. Use these features only in environments
where you accept that behavior.
