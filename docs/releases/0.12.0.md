# Harness 0.12.0

This release adds per-directory configuration and a `/reload` command, so you
can try MCP servers and model settings in one project without touching your
global config and without restarting. It also makes MCP more forgiving: a
server that fails to start no longer blocks the session, and codemode now tells
the model which servers exist.

## Changes

- A `.harness/config.toml` in the directory you launch from overrides the
  global config for that directory. It only needs the keys it changes. Tables
  merge key by key. `[[mcp.servers]]` entries match by `name` and replace the
  global entry completely, new names are added, and `enabled = false` switches a
  global server off for that directory.
- Workspace config must be trusted. It can start MCP servers and redefine
  providers, so it is ignored unless you launch with `harness --trust` or set
  `trust_workspace_config = true` in the global config. A workspace file cannot
  grant itself trust. The launch header gains a `config` row that says whether
  the override was applied or skipped, and Herdr resume commands repeat
  `--trust`.
- New `/reload` command. It re-reads the global and workspace config mid-session
  and applies provider, model, reasoning effort, MCP servers, codemode, skills,
  and `AGENTS.md` context, then prints the header again. New MCP servers connect
  first, so a required server that fails to start leaves the previous ones
  running and the notice says why. The notice lists each added server's command
  or URL with secrets redacted. `/reload` never writes a workspace value to the
  global config.
- MCP servers have a `required` setting, `false` by default. A server that fails
  to start is recorded with the tail of its stderr, shown as `failed to start`
  in the codemode roster, and reported as a notice (or a `-v` warning in
  headless mode), while the remaining servers still connect. Set
  `required = true` to keep the old behavior, where any failure stops startup.
- Stdio servers accept `cwd`, resolved against the workspace root.
  `harness mcp add` gains `--env`, `--cwd`, and `--required`.
- Codemode lists every MCP server in its description, shares its index budget
  fairly between servers, and prefers MCP tools over shell CLIs. The sandbox
  global `SERVERS` maps each server name to its instructions (capped at 1 KiB),
  tool names, and status.

## Fixes

- Streamable HTTP servers that reject the newer `server/discover` request with a
  4xx status, such as safari-mcp's `400 No valid session`, no longer fail
  startup. Harness retries with the older `initialize` handshake.
- MCP startup diagnostics are masked before they are shortened, so a length
  limit cannot leave the start of a secret visible. Server failure text and
  instructions also pass through the configured secret masker.
- A large number of failing servers no longer makes the codemode roster
  unbounded.

## Behavior changes

- A failing MCP server no longer stops startup unless it sets `required = true`.
  Check `harness` output or the TUI notice if a server you rely on looks
  missing.
- `.harness/config.toml` is ignored without `--trust` or
  `trust_workspace_config = true`. Setting the global option trusts every
  directory, including a fresh clone, so prefer the flag for projects you did
  not write.

## Known limits

- `/reload` waits for the current turn to finish and blocks while MCP servers
  connect (a few seconds). It reconnects every server when any change, so a
  server that holds state, such as a logged-in browser session, starts fresh.
- `rtk` is fixed when the session starts. `/reload` reports a change to it as
  needing a restart. Subagents keep the skills and context they started with.
- Custom providers added to the config after launch are not picked up by
  `/reload`. Commands such as `/model` still save to the global config file.

## Installation and upgrade

Run `harness update` after 0.12.0 is published. The supported CLI builds are:

- macOS on Apple silicon (`aarch64-apple-darwin`).
- macOS on Intel (`x86_64-apple-darwin`).
- Linux x86-64 with glibc 2.35 or newer (`x86_64-unknown-linux-gnu`).
- Linux arm64 with glibc 2.35 or newer (`aarch64-unknown-linux-gnu`).

Each archive includes the binary, README, header image, and MIT license. Use the
attached `SHA256SUMS` file to verify a downloaded archive, and
`gh attestation verify` to check its build provenance.

To install this version with the installer:

```sh
curl -fsSL https://raw.githubusercontent.com/alexlayton/harness/main/install.sh \
  | bash -s -- --version v0.12.0
```

The Python API is still a source-installed MVP. This release does not publish a
PyPI package or prebuilt wheels:

```text
harness-agent @ git+https://github.com/alexlayton/harness.git@v0.12.0
```

Harness still runs tools without confirmation. Bash and MCP tools have the
access of the operating-system user. Use these features only in environments
where you accept that behavior.
